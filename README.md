# 상당 현장 ON

**청주상당경찰서 지역경찰 대응역량 강화를 위한 웹 기반 교육·현장지원 플랫폼**

HTML · CSS · JavaScript · JSON으로 만든 정적 웹사이트입니다. 서버, 데이터베이스, 외부 CDN, API 키 없이 GitHub Pages에서 운영합니다. 홈, 매뉴얼 ON, 교육 ON, 알림 ON, 사례 ON, 통합검색, 게시물 편집 도우미를 포함합니다.

> 포함된 게시물 16건(메뉴별 4건), PDF 3개, 카드뉴스 3장은 모두 기능 확인용 가상 예시입니다. 실제 지침·사건·교육 일정을 뜻하지 않습니다. 실제 자료 등록 전 공개 가능 여부와 내용의 정확성을 확인하세요.

**PC에서 바로 확인하기**

- 바로 확인하려면: [제작 확인용 사이트](https://sangdang-field-on.goldburg18.chatgpt.site) 접속
- 직접 운영하려면: 아래 순서로 GitHub Pages 설정 후 발급된 주소로 접속
- `index.html`을 더블클릭한 경우: 실행 안내 표시 · 게시판은 HTTP·HTTPS 주소에서 이용
- 내 PC에서 수정한 내용: 확인용 사이트에 자동 반영되지 않음 · 로컬 확인 방법은 6절 참고

## 1. 처음 시작하기 — GitHub Pages로 공개

### 1단계. 운영계정과 저장소 만들기

1. GitHub에서 운영에 사용할 계정으로 로그인합니다. 계정 생성은 담당자가 직접 진행합니다.
2. 오른쪽 위 **+ → New repository**를 선택합니다.
3. **Repository name**에 `sangdang-field-on`을 입력합니다. 다른 영문 이름도 가능합니다.
4. 무료 공개 운영의 예로 **Public**을 선택합니다. 공개 저장소의 파일과 수정 기록은 다른 사람도 볼 수 있습니다.
5. **Add a README file**을 선택해 `main` 브랜치를 만든 뒤 **Create repository**를 누릅니다.

### 2단계. 프로젝트 파일 올리기

1. 제공된 ZIP의 압축을 풉니다.
2. 압축을 푼 `sangdang-field-on` 폴더 안으로 들어갑니다.
3. GitHub 저장소에서 **Add file → Upload files**를 선택합니다.
4. `index.html`, `pages`, `data`, `files`, `assets`, `tools`, `README.md`, `404.html` 등을 함께 끌어 놓습니다.
5. **중요: 바깥쪽 sangdang-field-on 폴더 자체가 아니라 그 안의 파일·폴더를 올립니다.** 저장소 첫 화면에서 `index.html`이 바로 보여야 합니다.
6. 변경 설명에 `상당 현장 ON 최초 등록`을 적고 **Commit changes**를 누릅니다. 기존 README를 교체한다는 안내가 나오면 제공된 README를 사용합니다.
7. `.nojekyll`도 함께 올립니다. 파일이 숨겨져 보이지 않으면 GitHub의 **Add file → Create new file**에서 파일명을 `.nojekyll`로 입력하고 빈 파일로 저장할 수 있습니다.

**ZIP 파일 하나만 업로드하면 사이트가 만들어지지 않습니다. 반드시 압축을 푼 파일을 올립니다.**

### 3단계. GitHub Pages 활성화

1. 저장소의 **Settings**를 엽니다.
2. 왼쪽 메뉴의 **Pages**를 선택합니다.
3. **Build and deployment → Source**에서 **Deploy from a branch**를 선택합니다.
4. **Branch**는 `main`, 폴더는 `/(root)`로 선택하고 **Save**를 누릅니다.
5. 저장소의 **Actions** 또는 **Settings → Pages**에서 배포 완료를 확인합니다. 반영은 즉시 완료되지 않을 수 있습니다.
6. Pages에 표시된 **Visit site**로 접속합니다. 일반적인 프로젝트 주소 형식은 `https://계정명.github.io/sangdang-field-on/`입니다. 실제 주소는 GitHub가 표시하는 값을 사용합니다.
7. 휴대전화에서도 접속해 4대 메뉴와 PDF를 확인합니다.

이 프로젝트는 별도 빌드 명령이나 npm 설치가 필요하지 않습니다. GitHub에 올린 정적 파일을 그대로 제공합니다. 계정·조직의 요금제와 정책에 따라 공개 가능한 저장소 종류와 메뉴가 다를 수 있습니다.

## 2. 가장 쉬운 게시물 등록 — 편집 도우미 사용

- 여는 방법: 사이트 하단의 **게시물 편집 도우미** 선택
- 주소로 열 때: 사이트 주소 끝에 `/tools/editor.html` 추가
- JSON: 제목·본문·첨부 경로 등 게시물 목록을 담는 파일
- 사이트에 반영하려면: 도우미에서 내려받은 JSON을 GitHub에 업로드
- 업로드 권한: 해당 GitHub 저장소에 쓰기 권한이 있는 담당자 필요

### 게시물 등록 순서

1. PDF·이미지 파일명 정하기 — 영문 소문자·숫자·하이픈 권장 (예: `training-01.jpg`)
2. GitHub의 해당 `files` 폴더에서 **Add file → Upload files → Commit changes**로 실제 파일 업로드
3. 사이트의 **게시물 편집 도우미**를 열고 메뉴 선택 — 기존 게시물 목록 자동 불러오기
4. **새 게시물** 또는 수정할 게시물 선택
5. 아래 ‘입력칸별 안내’를 참고해 제목·본문·첨부자료 입력
6. 입력을 마치면 **목록에 반영** 선택 — 다른 게시물도 이어서 수정 가능
7. **JSON 다운로드** 선택 — 현재 메뉴의 전체 게시물이 파일 하나로 저장
8. GitHub의 **data 폴더 → Add file → Upload files**에서 내려받은 JSON을 같은 이름으로 업로드
9. 변경 설명 입력 후 **Commit changes** 선택 — 배포 완료 뒤 사이트를 새로고침해 확인

### 입력칸별 안내

| 입력칸 | 입력 방법 |
| --- | --- |
| 제목·분류·등록일 | 필수 입력 · 분류는 목록에서 선택하거나 직접 입력 |
| 요약내용 | 게시물을 열었을 때 먼저 보일 핵심 내용 입력 |
| 본문 | 일반 글처럼 입력 · 줄을 바꾸려면 Enter |
| 대표 첨부파일 경로 | 올려 둔 파일의 위치 입력 (예: `files/manuals/missing-child.pdf`) · 앞에 `/`는 붙이지 않기 |
| 이미지 경로 | 먼저 보여줄 이미지부터 한 줄에 한 경로씩 입력 |
| 추가 첨부자료 — 자료 이름 | 화면에 보일 이름 입력 (예: `교육 활동지` 또는 `me01`) |
| 추가 첨부자료 — 파일 경로 | 올려 둔 파일의 위치 입력 (예: `files/education/me01.pdf`) |
| 태그 | 검색에 쓸 단어를 쉼표로 구분해 입력 (예: `주취자, 현장대응`) |
| 중요 · 상단 고정 | 중요순 정렬에서 먼저 보여줄 게시물에 체크 |
| 가상 예시 자료 | 기능 확인용 예시에 체크 · 실제 운영자료는 체크 해제 |
| 게시물 ID | 새 게시물은 자동 생성 · 기존 게시물은 연결 주소를 유지하도록 그대로 사용 |
| 발생 개요·주요 조치·시사점 | 사례 ON에서 각 항목에 맞는 내용 입력 |

- 첨부자료가 여러 개라면: **첨부자료 추가** 선택
- 필요 없는 첨부자료는: 해당 줄의 **삭제** 선택
- 이름·경로 중 하나만 적었다면: 나머지 칸도 입력한 뒤 목록에 반영
- 이름·경로가 모두 빈 줄: 저장할 때 자동으로 제외
- 긴급 알림을 올리려면: 알림 ON의 분류에 `긴급` 입력 — 긴급 배지 표시

### 작업할 때 기억할 내용

- **목록에 반영:** 현재 창의 작업 목록만 변경 · 사이트에는 아직 반영되지 않음
- **PDF·이미지:** 경로 입력과 별도로 실제 파일도 GitHub에 업로드
- **창을 닫기 전:** JSON 다운로드 필수 · 내려받지 않은 작업은 사라짐
- **파일명 확인:** `manuals (1).json`으로 저장됐다면 `manuals.json`으로 바꾼 뒤 업로드
- **여러 명이 수정할 때:** 작업 순서를 정하고, 시작 전 새로고침으로 최신 목록 확인 · 동시에 올리면 앞선 변경이 덮일 수 있음
- **이어서 수정할 때:** ‘저장해 둔 JSON 불러오기’ 선택 후 해당 파일과 메뉴가 맞는지 확인
- **게시물을 삭제할 때:** JSON에서 게시물만 삭제 · 사용하지 않는 PDF·이미지는 다른 게시물의 사용 여부를 확인한 뒤 GitHub에서 별도로 정리
- **목록을 읽지 못할 때:** 편집을 멈춘 상태에서 JSON 오류를 고치거나 정상 백업 파일 불러오기

## 3. GitHub에서 JSON을 직접 수정하는 방법

1. PDF·이미지를 지정된 `files` 폴더에 먼저 올립니다.
2. `data/manuals.json` 등 해당 JSON을 엽니다.
3. 연필 모양 **Edit this file**을 누릅니다.
4. 기존 `{ ... }` 게시물 한 개를 복사합니다.
5. `id`, 제목, 분류, 날짜, 본문, 파일 경로 등을 수정합니다. **ID는 같은 메뉴 안에서 중복되면 안 됩니다.**
6. 게시물과 게시물 사이에는 쉼표가 필요합니다. 마지막 게시물 뒤에는 쉼표를 쓰지 않습니다.
7. **Commit changes**를 누르고 배포 완료 뒤 확인합니다.

한 개의 게시물만 있는 파일 예시:

```json
[
  {
    "id": "manual-005",
    "title": "공개용 현장 참고자료",
    "category": "기타",
    "date": "2026-09-11",
    "important": false,
    "summary": "자료의 핵심 내용을 짧게 입력합니다.",
    "content": "첫 번째 문단입니다.\n\n두 번째 문단입니다.",
    "file": "",
    "images": [],
    "tags": ["참고자료", "현장대응"],
    "sample": false
  }
]
```

`file`은 PDF 업로드 후 `files/manuals/파일명.pdf`로 입력합니다. 첨부가 없으면 빈 문자열 `""`을 유지합니다.

### 데이터 항목

| 항목          | 입력 방법                                                                 | 필수 여부        |
| ------------- | ------------------------------------------------------------------------- | ---------------- |
| `id`          | 중복 없는 영문·숫자·하이픈·밑줄. 기존 게시물 ID는 변경하지 않는 것을 권장 | 필수             |
| `title`       | 화면에 표시할 한글 제목                                                   | 필수             |
| `category`    | 분야·교육 분류·알림 구분·사례유형                                         | 필수             |
| `date`        | 실제 등록일, `YYYY-MM-DD`                                                 | 필수             |
| `important`   | 상단 고정은 `true`, 일반은 `false`                                        | 선택, 기본 false |
| `summary`     | 상세화면 상단에 먼저 표시할 요약                                          | 선택             |
| `content`     | 일반 텍스트 본문. 줄바꿈은 `\n`                                           | 선택             |
| `file`        | 대표 PDF 또는 첨부파일의 상대경로                                         | 선택             |
| `images`      | 이미지 상대경로 목록. 순서대로 표시                                       | 선택             |
| `tags`        | 통합검색에 사용할 태그 목록                                               | 선택             |
| `overview`    | 사례의 발생 개요                                                          | 사례 선택 항목   |
| `actions`     | 사례의 주요 조치                                                          | 사례 선택 항목   |
| `lessons`     | 사례의 시사점                                                             | 사례 선택 항목   |
| `attachments` | 여러 첨부자료가 필요한 경우 아래 형식 사용                                | 선택             |
| `sample`      | 가상 예시 표시. 실제 공개 자료는 false 또는 생략                          | 선택, 기본 false |

추가 첨부자료 예시:

```json
"attachments": [
  {"name": "활동지", "path": "files/education/workbook.pdf"},
  {"name": "참고자료", "path": "files/education/reference.pdf"}
]
```

### 분류와 표시 규칙

- 매뉴얼: 주취자, 폭력, 절도, 실종, 가정폭력, 아동·청소년, 교통, 기타.
- 교육: 카드뉴스, FTX, 직무교육, 기타.
- 알림: 긴급, 일반. `important: true`가 상단 고정 기준입니다. **긴급 표시와 상단 고정은 서로 별개**이므로 긴급 공지를 고정하려면 두 값 모두 설정하세요.
- 사례: 우수사례, 미흡사례, 현장 대응사례.
- 기존 분류 외의 값을 입력하면 해당 메뉴의 필터에 자동 추가됩니다.
- 기본 정렬: 중요 게시물 우선 → 등록일 내림차순. 사용자가 최신순 또는 제목순으로 바꿀 수 있습니다.
- NEW: 이용 기기의 오늘 날짜 기준, 등록 당일을 포함해 최근 14일 차이 이내인 게시물. 미래 날짜에는 표시하지 않습니다. 등록일을 임의로 바꾸어 최신 자료처럼 보이게 하지 마세요.
- 홈 최근 자료: 등록일 기준 최신 5건. ‘꼭 확인하세요’: 긴급 또는 중요 알림 중 최대 2건.
- 목록은 10건씩 나눠 표시합니다. 알림의 번호는 원자료 전체의 등록일·ID 정렬에 따라 계산합니다. 삭제·날짜 변경 시 번호가 달라질 수 있습니다. 중요 공지는 번호 대신 고정 아이콘을 표시합니다.
- 검색: 제목·요약·본문·카테고리·태그·사례 개요/조치/시사점. 띄어 쓴 여러 검색어는 모두 포함하는 자료를 찾습니다. **PDF 내부의 글자, 이미지 속 글자, OCR 검색은 지원하지 않습니다.** 필요한 검색어를 본문과 태그에 함께 적으세요.

CI를 바꾸려면 `assets/images/logo.png`를 같은 이름으로 교체하면 됩니다. 정사각형 PNG를 권장하며 화면에서는 원본 비율을 유지합니다. 제공된 로고는 재작화하거나 색을 바꾸지 않았습니다.

파일명은 영문·숫자·하이픈을 권장합니다. **대소문자를 구분**하므로 `Guide.pdf`와 `guide.pdf`는 다른 파일입니다. JPG·JPEG·PNG·WebP 등 일반적인 이미지 형식을 사용할 수 있습니다. SVG를 새로 등록할 때에는 직접 검토한 신뢰 가능한 파일만 사용합니다. 낯선 SVG에는 코드가 포함될 수 있으므로 일반 운영자료는 PNG·JPG를 권장합니다.

## 5. 보안·공개 범위

이 사이트는 **외부 인터넷에 공개 가능한 자료만** 게시하는 구조입니다. 직원이 주요 이용자라는 사실이 직원 전용 접근통제를 의미하지 않습니다. URL을 아는 사람만 접속하도록 안내하거나 검색 노출을 줄이는 방식도 보안 장치가 아닙니다.

게시 금지 자료:

- 개인 이름·주민등록번호·전화번호·개인 차량번호 등 개인정보
- 사건 관계자 정보, 얼굴·명찰 등이 드러나는 사진, 정확한 사건 주소
- 상세 112 신고내용·원자료·좌표, 내부 비공개 지침, 비공개 전술·보안자료
- 계정 비밀번호, GitHub 토큰, API 키, 인증서·내부 접속정보

운영 시 확인사항:

1. 게시 담당자와 검토 담당자를 정하고 공개 가능한 범위를 확인합니다.
2. PDF 본문·사진·문서 속성·이미지 위치정보 등 첨부파일도 확인합니다. 검은 도형으로 가리는 것만으로 원문이 제거되지 않는 경우가 있으므로 실제 정보가 제거된 배포본을 사용합니다.
3. 공개 저장소의 삭제 전 자료는 Git 수정 기록에 남을 수 있습니다. 민감자료가 잘못 게시되면 새 커밋에서 파일만 지우는 것으로 충분하다고 판단하지 말고 기관 절차에 따라 조치합니다.
4. GitHub 운영계정에는 2단계 인증을 적용하고 담당자 변경 시 권한·복구수단을 인계합니다.
5. 내부 전용자료가 필요하면 기관이 승인한 인증·접근통제 체계가 있는 별도 환경을 사용해야 합니다. 이 정적 사이트에는 보안을 보장하는 로그인 기능이 없습니다.
6. 운영 자료는 기관의 외부 게시·홍보물·CI 사용 방침에 맞추어 등록합니다.

기술상 JSON 본문은 HTML로 실행하지 않고 글자로 표시합니다. `javascript:` 같은 첨부 주소를 차단합니다. 외부 자료 연결은 HTTPS만 허용합니다. 이 처리는 내용의 공개 가능성을 대신 판단하지 않습니다. 외부 분석·광고·사용자 추적 코드, 서비스 워커, 자동 캐시 보관은 넣지 않았습니다. JSON은 매 접속 시 최신 내용을 요청하지만 GitHub Pages/CDN 배포 반영까지의 지연은 있을 수 있습니다.

## 6. 문제 해결

| 증상                                         | 확인 방법                                                                                |
| -------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 홈에 404가 표시됨                            | `index.html`이 저장소 첫 단계에 있는지, Pages가 `main / (root)`인지 확인                 |
| 내 PC에서 파일을 더블클릭하면 자료가 안 보임 | `file://`에서는 JSON 요청이 제한됩니다. GitHub Pages의 HTTPS 주소에서 접속               |
| 자료를 불러오지 못했다는 안내                | JSON의 쉼표·따옴표·괄호, 중복 ID, 날짜 형식, 데이터 파일명 확인                          |
| PDF·이미지가 열리지 않음                     | 실제 업로드 여부, 폴더 위치, 영문 대소문자, 확장자 확인. 페이지 기준 `../`를 붙이지 않음 |
| 새 게시물이 안 보임                          | 파일명에 `(1)`이 붙었는지, 올바른 메뉴 JSON인지, 배포가 완료됐는지 확인 후 새로고침      |
| 중요 공지가 맨 위에 없음                     | `important`가 문자열 `"true"`가 아닌 불리언 `true`인지, 정렬을 바꾼 상태인지 확인        |
| 본문에서 줄바꿈이 사라짐                     | 직접 편집은 `\n` 사용. 도우미에서는 Enter로 줄바꿈                                       |
| 스마트폰에서 PDF가 새 탭·별도 뷰어로 열림    | 정상적인 브라우저 동작입니다. 휴대전화 설정에 따라 PDF가 다운로드될 수도 있음            |
| 큰 파일을 웹에서 올리지 못함                 | GitHub 웹 업로드는 파일당 25 MiB 제한. PDF 용량을 줄이거나 승인된 다른 배포 경로 검토    |

개발자가 로컬에서 확인하는 경우, `index.html`이 있는 폴더에서 `python -m http.server 8000 --bind 127.0.0.1`을 실행한 뒤 `http://127.0.0.1:8000/`에 접속할 수 있습니다. 종료는 Ctrl+C입니다. Python이 설치된 PC에서만 가능한 선택사항이며, GitHub Pages 운영에는 필요하지 않습니다.

## 7. 인수인계·정기 점검

계획서의 운영방향에 따라 월 1회 이상 게시자료의 최신성·공개 가능성·첨부파일을 확인합니다. 계정·저장소 주소·Pages 주소·운영 담당자·정기 점검일을 기관 내부 인계문서에 기록하고, 비밀번호는 이 저장소에 적지 않습니다. 수정 전에는 해당 JSON의 기존 내용을 내려받아 두고 변경 이유를 Commit 설명에 남깁니다.

초기 예제를 제거할 때는 각 메뉴의 배열을 `[]`로 저장해도 됩니다. 게시물이 없는 경우 안내문이 표시되며 오류로 처리하지 않습니다. 실제 자료는 `sample`을 `false`로 저장하거나 해당 항목을 생략합니다.
